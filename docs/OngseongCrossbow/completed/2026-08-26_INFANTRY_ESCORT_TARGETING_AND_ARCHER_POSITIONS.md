# 보병 호위·총통 표적·궁병 공격 포지션 수정

## 결과

* 검병은 충차의 고정 슬롯을 계속 유지하지 않는다. 멀어지면 달려가고, 근처에서는 멈추거나
  분산된 구역 주변을 랜덤 배회한다.
* 아군 총통은 적 궁병과 검병을 모두 자동 사격 대상으로 포함하고 충차는 제외한다.
* 궁병은 성벽 위 총통 Actor로 직접 경로를 요청하지 않는다. 성벽 안쪽 NavMesh의 공격 포지션
  `TargetPoint`를 예약해 이동하고, 가장 가까운 총통을 별도 사격 표적으로 사용한다.

## 구현

`AOngseongEnemyWaveManager`가 `Ongseong.ArcherAttackPosition` 태그를 가진 `TargetPoint`를
검색해 궁병 한 명당 하나씩 예약한다. 사망·퇴각·Pool 반환 시 예약을 즉시 반납한다.
`BT_EnemyArcher`의 `Move To` 허용 반경은 1800cm에서 100cm로 바꾸고 부분 경로를 껐다.
공격 포지션 8개는 본편 `LV_Ongseong`과 `LV_Ongseong_CombatTest` 양쪽에 동일하게 배치했다.

검병은 700cm 추종 진입 / 450cm 정착의 히스테리시스를 사용한다. 추종 속도는 180cm/s,
근거리 배회 속도는 90cm/s이며 2.5~5초마다 선호 구역 주변 160cm 안에서 NavMesh 목적지를
다시 고른다. 실제 스폰 위치도 authored marker에서 NavMesh로 투영한다.

## 검증

* Editor 모듈 빌드 성공
* PIE에서 궁병 공격 포지션 이동 요청 7건 전부 `accepted=1`
* 측정 시 6명은 슬롯에 도착, 1명은 `MOVE_Walking`, XY 속도 약 600cm/s로 이동 중
* 아군 총통 로그에서 적 검병과 적 궁병 양쪽 사격 확인
* 검병 추종 180cm/s, 배회 90cm/s 이동 요청 승인 및 실제 속도 10cm/s 초과 확인

검병 Run 전이 입력은 `GetVelocity().Size2D()`이므로 애니메이션 문제의 원인은 10cm/s 임계값이
아니라 이동 요청 부재였다. 현재 이동 중 실제 속도는 임계값을 충분히 넘는다.
