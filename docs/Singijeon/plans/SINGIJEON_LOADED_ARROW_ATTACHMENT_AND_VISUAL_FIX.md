# 목적

**상태: 완료 (2026-08-22)**

화차 운반 중 장전 화살이 화차와 함께 이동하지 않는 문제, 발사된 슬롯 외형이 남는 문제, 최초 물리 화살의 머터리얼 누락을 함께 수정한다.

# 현재 상태

- 자동 채움 ISM은 `RackRoot` 자식이지만 생성 좌표와 실제 컴포넌트 좌표계가 일치하는지 런타임 검증이 부족하다.
- 최초 물리 화살은 슬롯에 Actor Attach되지만 Blueprint Grab/물리 상태 및 메시의 절대 Transform 설정이 남아 있으면 부모 이동을 따르지 않을 수 있다.
- 순차 발사는 랜덤 인덱스를 제거하지만 실제 발사 Spawn과 남은 ISM 표시의 일치 여부를 검증하지 않는다.
- 머터리얼 검증이 CDO/에셋 설정만 검사하여 플레이 중 최초 장전 액터의 실제 동적 상태를 놓칠 수 있다.

# 구현 범위

- 물리 화살과 자동 채움 ISM의 부모/로컬 Transform 강제
- 발사 한 발당 정확히 하나의 표시 제거와 Spawn 성공 검증
- 최초 장전 화살을 포함한 모든 발사체 메시 머터리얼 보정
- Blueprint, 레벨, 자동화 테스트 및 에셋 검증 보강

# 변경 예정 파일

- `GF_Singijeon` 화차·탄약 슬롯·발사체 C++와 테스트
- 화차/화살 Blueprint와 관련 구성·검증 스크립트
- 신기전 명세·상태·완료 문서

# 구현 단계

1. 실제 CDO·배치 컴포넌트의 Attach/절대 Transform/머터리얼 상태 진단
2. 장전 시 로컬 Transform과 렌더 상태 정규화
3. ISM 좌표 및 발사 제거 로직 수정
4. BP 반영, 빌드·자동화·에셋 검증

# 다른 Feature에 미치는 영향

`GF_Singijeon` 내부로 한정하며 Core와 `docs/ARCHITECTURE.md`는 수정하지 않는다.

# 검증 방법

- 장전 후 화살 Actor와 ISM이 화차 이동 Delta를 동일하게 따르는지 자동 검증
- 각 발사마다 표시 수와 장전 수가 정확히 하나씩 감소하는지 검증
- 최초 물리 화살, 자동 채움 ISM, 발사 Spawn 모두 동일한 프로젝트 머터리얼을 사용하는지 검증
